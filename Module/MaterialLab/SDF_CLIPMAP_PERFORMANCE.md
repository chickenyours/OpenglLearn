# Global SDF Clipmap 性能验证

本轮优化针对茶壶宴会中四级 Global SDF 的三维可视化。原来全局距离场视图在 1280 × 800 下仅 GPU 就需要约 196 ms；截图中的 CPU 更新为零，说明持续低帧率主要来自逐像素求交，而不是重新合并距离场。

## 测量条件

- NVIDIA GeForce RTX 4060 Laptop GPU，Vulkan，1280 × 800，单样本。
- 使用同一场景、相机、四级 `64³` Global 距离场、24 / 48 / 128 MDF 输入和薄壁偏移；没有降低画面分辨率、距离场精度或茶壶数量。
- 构建目录为 `build/sdf-banquet`，配置是带 `/O2 /Ob2` 优化的 **Debug**，不是 Release。
- 等待 MDF 后台烘焙完成，每个静态案例预热后测量 6 帧均值。移动案例单独测量四次相机跨砖块的更新。
- 计时批次关闭 present、帧率限制与诊断回读；截图在计时外保存。`elapsed_ms` 是实际计时批次平均整帧耗时，`gpu_ms` 是 GPU 时间戳。

原始日志：[优化前](../../build/sdf_perf_before_vulkan.log)、[优化后](../../build/sdf_perf_final_vulkan.log)。短批次容易受 GPU 频率、系统负载和 HUD 上传影响，结果用于定位这次改动的收益，不代表所有机器上的稳定交互帧率。不能把 `1000 / gpu_ms` 当作实测整帧 FPS。

## 测量结果

单位均为 ms；GPU 与整帧分别比较。

| 场景 | GPU 前 → 后 | 整帧前 → 后 |
|---|---:|---:|
| 仅原始模型，对照 | 1.084 → 3.953 | 2.228 → 6.005 |
| 原始模型与探针追踪，对照 | 3.012 → 15.535 | 5.281 → 19.299 |
| Global 总览，不叠加边框与 HUD | 196.056 → 7.955 | 198.908 → 9.109 |
| Global 总览，边框与 HUD | 199.312 → 8.079 | 207.922 → 15.360 |
| Global 近景 | 220.762 → 6.953 | 223.022 → 8.345 |
| Mesh 视图 | 17.409 → 34.877 | 19.590 → 36.492 |
| Mesh / Global 分屏 | 149.132 → 28.141 | 151.175 → 31.035 |
| 相机移动，四次更新均值 | 197.249 → 5.267 | 230.394 → 31.367 |

Global 总览的 GPU 开销降到约原来的 1/24.65；包括 HUD 的总览整帧由约 4.81 FPS 提高到约 65.11 FPS，均来自日志中的整帧耗时。这里不把 GPU 8 ms 写成“整帧 125 FPS”。

移动案例平均 CPU Clipmap 更新由 18.804 ms 降至 6.696 ms，约为原来的 1/2.81；两次移动测量平均更新、上传的 Global texel 均为 20,480，更新工作量相同。

这组短批次也记录了未改善的部分：Mesh 视图由 17.4 ms 增至 34.9 ms；纯模型、原探针路径两个控制项也明显变慢。本轮已验证的主要收益是 Global 求交与 CPU Clipmap 更新，不能宣称所有视图均提速。控制项说明两次短批次存在明显波动，但没有单独测量出波动原因，不能把硬件频率或系统负载当作已证实的解释，也不能据此扣除或修正表中的耗时。

## 改动

### 不再为 Volume 视图生成无用射线

Mesh / Global / 分屏三维视图只需要相机常量与距离场纹理。它们现在跳过屏幕探针捕获、候选生成、HZB、屏幕追踪及 SDF 补追，也不为这些路径分配射线目标。Volume 模式不再每秒同步回读探针和射线，只刷新 FPS。切回探针视图后重新生成位置与射线，避免显示上一次模式留下的数据；原 GI 追踪功能仍保留。

性能日志中的 Global 视图由 `placement=6, trace=14, hzb=11` 变为 `placement=0, trace=1, hzb=0`。这里的 pass 统计是管线中的分类计数，`trace=1` 表示距离场可视化，不是仍执行了一遍屏幕追踪。

### 以砖块区间跳过空区域，精确求解实际纹理零面

每个 `4³` 体素单元砖块保存一个最小值、最大值区间。区间覆盖 `5³` 个节点，包含下一砖块共享的角点；物理环形存储发生滚动时，受影响砖块及负轴邻居一并更新。三线性插值不会超出其角点数值范围，因此同号区间可以安全跳过整个砖块。

可能包含零面的砖块采用 DDA 逐单元前进。一个单元的八个角点只读取一次；沿射线的三线性插值是三次多项式，按导数临界点划分单调区间后，寻找第一个真实根。求交使用原始距离场数据，没有把模型三角形、粗级替身或重着色当作命中结果。

命中后才计算原来的半体素差分平滑法线，保留已有着色效果；求根过程中不再重复计算这组法线采样。每条射线也只预先计算四级盒子的进出区间，避免每步重复求盒交。Clipmap 边界的 48 条线段改为 CPU 投影，GPU 直接使用投影端点。

Mesh、Global、分屏三种视图分别懒编译为常量模式，避免单个大型 shader 为所有路径保留工作量。离线优化后的 Vulkan SPIR-V 分别为 35,092、158,816、187,880 字节；Mesh 变体中已删除 Global 与区间纹理读取。这确认了无用分支被消除，但编译产物大小不能证明寄存器占用或性能收益，Mesh 的实测结果仍见上表。

### CPU 更新复用工作线程

大脏区按物理砖块分配到最多八个工作线程，线程池延迟创建并反复使用；每个任务独占自己的物理砖块。小脏区走串行路径。没有变化的帧不提交砖块任务，也不唤醒工作线程。

并行热点内改用指针索引访问对象与样本，避免 MSVC Debug 受检容器在每个体素的 range-for 中反复注册、释放迭代器而争用全局锁。早期并行版本的移动 CPU 时间曾退化到约 60 ms；定位并修复这一争用后，保留线程池的最终结果为 6.696 ms。线程数量本身不保证加速，最终数据包含了区间纹理的新增 CPU 维护工作。

## 画面对照

同一总览视角的 [优化前](../../build/sdf_perf_before.png) 与 [优化后](../../build/sdf_perf_final.png) 截图均为 1280 × 800。去掉顶部 225 行 HUD 区域后，RGB 绝对差均值约为 0.007（0–255 范围），99 百分位为 0，差值超过 16 的像素约占 0.0118%。这组对照确认主要画面保持一致；它只覆盖此视角，不能代替跨层级、滚动和动态物体的命中回归。

## 上传与开销边界

原有 `uploaded` / `probeSdfUploadedTexels` 统计仍只统计 Global 距离图集，不包含新增加的区间图集。四级场景的区间图集总共 16,384 个 RGBA32F texel，**每个 Global generation 发生变化的帧额外上传 256 KiB**；静止且无物体变化时上传为零。

区间图集采用一次完整小纹理上传，Global 距离图集仍按实际脏区上传。跳过多帧后重新启用时，两份纹理分别补齐到最新 generation，防止区间与距离数据不同步。

## 复现

最终构建的四项 CPU 回归通过，包含并行与串行逐 bit 对照、共享角点 min/max 及滚动/动态更新。Clipmap 的 [Vulkan validation](../../build/sdf_clipmap_optimized_vulkan.log) 与 [OpenGL](../../build/sdf_clipmap_optimized_opengl.log) 回归均通过，GPU 完整距离与区间图集和 CPU 一致；真实纹理零面重采样的最大残差约 `1.47e-5`。还通过了旧固定体积的 [Vulkan 质量](../../build/sdf_perf_legacy_quality_vulkan.log)、[OpenGL 质量](../../build/sdf_perf_legacy_quality_opengl.log) 和 [屏幕补追](../../build/sdf_perf_legacy_trace_vulkan.log) 回归。

临时提取实际 GLSL 求根函数，用独立双精度角点插值、密集采样及二分核对：8 组已知根、20,000 条随机射线中 7,094 条真实横穿均未漏失；另验证近零恒正/恒负场保持未命中。四个 shader 模式（动态、Mesh、Global、分屏）的两后端共八个变体均通过离线编译及 SPIR-V 验证。

```text
output\sdf-banquet\Debug\bin\material_lab_demo.exe --vulkan --sdf-clipmap-performance-test --render-width 1280 --render-height 800 --msaa 1 --screenshot build/sdf_perf_final.png
```

交互入口仍为 `Module\MaterialLab\RunSdfBanquet.cmd`，默认限制 60 FPS。需要观察不受此限制的帧率时使用：

```text
Module\MaterialLab\RunSdfBanquet.cmd --fps 0
```
