# 头发二次运动资产与预览

## 范围与资产结构

头发使用已有骨骼链驱动实际蒙皮网格，提供惯性、重力、回复、阻尼和角度约束，再通过局部网格接触处理头部、肩膀及手臂。头发几何仍由人物的 Skeletal Mesh 持有，独立的 `HairAsset` 保存模拟配置和绑定。整体运动由发骨承担，局部接触只修正需要避让的发片，保留原有材质和 Toon 绘制方式。

```text
MahiroCloth/
  Character.asset.json        # 可选 hairPhysics 相对引用
  Body/Package.asset.json     # 骨架、主体和头发几何、蒙皮、表情、动画
  Garments/Skirt/             # 已分离的裙摆几何
  Cloth/Skirt.cloth.json      # 裙摆模拟资产
  Hair/Hair.hair.json         # 独立头发模拟资产，无重复纹理/几何
  Hair/Hair_Realtime30.hair.json # 30 Hz 接触 / 120 Hz 骨骼子步的独立预览配置
```

旧人物资产没有 `hairPhysics` 字段时仍可加载。加载头发时校验骨架、单位、绑定、蒙皮与网格拓扑，错误配对不会进入模拟。导出人物到新目录时一并保存头发配置；禁止越界引用，并沿用资产导出的验证和发布流程。

真寻源 PMX 含 55 个实际头发骨、17 条链和完整刚体/弹簧关节。生成器保留所有原始物理记录，选取 16 条具有有效网格影响的链、50 个必要骨骼，剔除整条零蒙皮权重的辅助链。6 个头发材质区含 16,014 个渲染顶点，其中 10,702 个具有实际头发骨的正权重；其余区域沿用源蒙皮。`HairBack` 的 760 个顶点没有头发链权重，会继续刚性跟随头部。

这些数据来自模型；VMD 动作包没有头发骨轨道或头发物理参数。扫描原始结论见 [HAIR_ASSET_SCAN.md](HAIR_ASSET_SCAN.md)。新导入器会保存 PMX 具体刚体和关节参数，之前只保存总数的旧 package 仍需从原 PMX 重新提取。

源模型部分发根埋在头皮内，还带有极小的后段蒙皮权重。生成器仅在绑定姿态中，以真实头部包围、碰撞三角的头骨权重和共享边连通性识别附着区。它从头部占主导的原始种子扩展，只接受根骨占主导、所有远端旋转引起的最大位移合计不超过 0.5 mm 的点；不依据播放时的穿透结果划区。加载时复核几何、连通与容量证据。

此区域不作为自由碰撞点推挤整束头发。计算位移容量时使用沿骨段的保守路径和尺度上界，为后段旋转预留预算，再限制第一段角度，令总头部局部漂移不超过 1.5 mm。头部外的刘海、不与原始种子连通的点和具有实质远端变形能力的发束继续碰撞。完全由附着点与原始头部刚性点组成的三角采样也不会错误推挤发束。

## 生成与检查

先构建 `hair_asset_import` 和 `skeletal_asset_editor`。使用原模型提取物理记录，使用最终人物 Body package 建立实际蒙皮绑定：

```powershell
.\output\Release\bin\hair_asset_import.exe `
  --source "C:\Users\16620\Downloads\真寻酱（女仆装）_by_Sa（艾拉漫剪）_07df9bce2f9eeb31bc903e14f16e8582\真寻酱（女仆装）\真寻酱（女仆装）.pmx" `
  --target Asset/Generated/MahiroCloth/Body/Package.asset.json `
  --output Asset/Generated/HairRevisions/MahiroHair01.hair.json `
  --name MahiroHair --physics-hz 60

.\output\Release\bin\hair_asset_import.exe `
  --inspect Asset/Generated/HairRevisions/MahiroHair01.hair.json `
  --target Asset/Generated/MahiroCloth/Body/Package.asset.json
```

输出必须是新路径，生成器不会覆盖已有修订。默认最多 512 个表面采样点，包含实际顶点与三角面内部采样；采样保存实际蒙皮影响，可在渲染前的骨骼姿态上求值。源刚体质量、阻尼、角度和弹簧记录完整保留，但模拟配置经过单位转换和有界映射，不能将 PMX 原值直接视为本求解器参数。

生成器使用保守的 20° 运行时摆动锥上限，发根再按附着预算收紧。PMX 的三轴 Euler 限制仍完整保存在源关节记录中；它们的向量长度不能直接作为任意方向的摆动半角，否则该模型每轴约 36° 会扩大成约 62°，接触时容易把整束头发推成横向展开。运行时 `maxAngle` 可在新资产修订中调整，本求解器没有逐项复现 PMX 刚体关节。

当前项目已附带 `MahiroCloth/Hair/Hair.hair.json` 和 `Hair_Realtime30.hair.json` 两份配置，人物清单的 `hairPhysics` 引用前者。重新从源生成时，使用上述命令的新输出路径保存 60 Hz 配置；将 `--physics-hz` 改为 `30` 并换一个新输出路径即可生成 30 Hz 配置，程序自动选择 4 个骨骼子步。经检查后可在编辑器加载该配置，并通过人物导出生成新的装配修订。仅生成独立文件不会自动修改已有 Character 清单。

## 在编辑器中操作

`Module/Model/RunMahiroHair.cmd` 打开头发专用预览，采用 30 Hz 接触、4 个骨骼子步，保留人物与裙摆的动画蒙皮，关闭裙摆物理。该频率与源 VMD 的 30 FPS 一致，窗口仍独立刷新。`RunMahiroCloth.cmd` 使用人物装配中注册的 60 Hz 头发配置，运行头发与裙摆联合模拟。

左侧选择 **Hair Physics / 头发惯性**：可开关模拟、显示骨骼链、冻结、从当前动画重新开始，调整惯性、真实表面接触余量及碰撞开关。可以选择链，查看原始刚体/关节索引、质量、弹簧、响应率、阻尼和角度限制；也可以加载兼容头发资产或将当前配置另存为新修订。

时间轴继续使用已有 VMD、动画序列及表情轨道。跳转和换配置会重置物理历史；自然播放使用固定步长。时间轴暂停时头发仍可在当前动画姿态上逐步静止。人物装配预览中的冻结按钮会保留整份已完成姿态，并取消未完成积压；解冻从保留时刻继续，冻结期间的跳转或重置请求会保留到恢复时处理。

## 每帧执行流程

1. 动画序列和表情曲线求值，完成已有骨架与 IK 姿态。
2. 人物表面碰撞结构只对保留的身体顶点做当前姿态蒙皮，并更新已有 BVH 包围盒。
3. 以米为模拟单位、双精度计算头发链的惯性、重力、回复、阻尼与约束；60 Hz 配置用 2 个子步，30 Hz 配置用 4 个子步，均使用 6 次结构迭代。
4. 具有已验证头皮附件和真实头发网格的资产，默认由骨骼处理惯性、由完整网格处理身体接触。有限骨骼自由度无法同时满足大量发片接触条件，因此不再让顺序粗骨投影与网格纠正互相争抢。缺少细网格的旧资产保留粗骨接触；有附件证据时，该路径可根据同链后段权重和头部归属过滤驱动旋转的采样。所有路径仍完整测量原始骨采样残留，不能把它直接当成最终渲染网格的穿透值。
5. 仅更新头发链的局部旋转；人物其他骨骼、局部位移和缩放、表情仍来自该次动画求值。发根固定在对应头部。同步 API 的零 tick 展示可跟随当前动画；异步窗口在两个物理 tick 之间保持上一份完成时刻的整个人物姿态，不额外插值成较新的身体。
6. 对可动头发顶点求值实际蒙皮位置。预先建立的空间分组先查询运动身体包围盒，只有可能接触的组才做连续三角形检测；局部修正沿拓扑平滑，并用当前身体再次检查修正轨迹。面接触作用于整组 UV 接缝顶点；顶点纠正会使相关面失效，最多四轮局部面/顶点交替处理，避免最终顶点检查重新破坏面接触。头皮附着区和纯头骨权重区域不接受网格位移。
7. 将修正保存为头部局部坐标中的位移，与对应骨架姿态一起发布。显示阶段先执行普通蒙皮，再应用该次修正并更新受影响法线，最后由现有 GPU 网格更新和 Material/Render/Toon 管线绘制。

碰撞造成的节点脱嵌位移不作为下一步的运动速度。接触速度采用零恢复处理，并衰减接触切向速度；否则位置投影会持续向发束注入动量，造成暂停动画后仍反复弹起。非接触时仍保留惯性、重力、回复与阻尼。

节点重建与接触修正共用父骨骼局部角限。不能再额外把每段限制在动画的世界方向锥内，否则多段累积弯曲会在两种坐标约束之间来回弹跳。身体几何不变、实际蒙皮输入和锚点输运仅有纳米级变化时，网格层停止人工位移衰减与拓扑扩散，保留接触形状；真实蒙皮位移、连续检测、接缝及面/顶点碰撞仍继续处理。

具有附件与真实细网格、使用网格接触的资产，还会在原始完整姿态和全部模拟设置精确不变，且节点运动、速度和实际偏移变化连续至少 30 tick、至少 1 秒低于纳米级门槛后休眠。休眠保持已经收敛的姿态和网格修正，逻辑时钟继续推进；骨骼、锚点、表情或设置改变会立即唤醒。零 tick 展示期间发生过的输入变化也会保留唤醒标记，显式重置清除休眠。此处理只停止数值舍入噪声，不能替代动态接触或用来冻结未解开的穿透。

人物装配中的头发单独预览、头发与裙摆联合预览，都使用同一个后台预览工作线程及完整人物姿态发布；关闭裙摆物理会跳过裙摆求解。联合预览将头发运行时步长对齐裙摆时钟，并调整骨骼子步数保持内部频率，避免不同配置频率造成中间身体姿态重复使用旧接触。源头发资产不被修改。暂停、恢复、重置和代际取消同时处理对应物理状态。直接打开普通骨骼 package 再加载头发的同步预览仍可使用；高负载时建议通过 Character 装配入口预览。

对已知骨架的后台中间时刻，先插值局部平移、旋转、缩放和表情，再按同一父子层级重组世界矩阵。不能独立插值每个骨骼的世界矩阵：父骨旋转时，子骨世界位置的弦与局部姿态生成的弧不同，会让身体接触、发根目标与实际蒙皮不一致。完整区间端点保留调用方的精确姿态；没有骨架元数据的通用布料输入继续使用原有矩阵插值。

最近面背侧不直接等同于身体内部。查询先区分连通表面，并以三个非轴向双向射线中的两组包围证据判定内部，避免将开放眼白或两片分离薄面之间的空气当成实体；薄面保留真实运动穿越检测。BVH 组件掩码、精确三角提示及双向共用遍历减少重复查询，优化测试与参考路径逐结果比较。

端点和自由面中心使用连通分量包围盒做保守内部候选查询，再进行真实包围检查。最近面朝向或固定查询距离不能证明点在身体外部，内层皮肤也不能遮住外层衣服的碰撞判定。组件包围盒有独立的小型 BVH，逐姿态更新；49 个固定方向的凸投影界进一步排除确定在组件凸包外的点，边界保留浮点容差并回退精确检查。该排除不依赖表面封闭，因为同组件双向有限交点的连线必须经过查询点。

UV 重复顶点按完整蒙皮、形变和实例轨迹硬绑定。相同轨迹、同一身体几何下未变的三角形查询可精确复用；真最近查询所得的外部结果只在同一身体对象、实际几何版本相同、世界坐标完全相同时复用。几何版本由真实身体顶点变化更新，可以跨静止物理步复用；开放衣服的内部分类可能在开口附近改变，因此没有用“附近点在外部”代替实际查询。

内部判定使用的三个固定方向还建立逐姿态更新的二维投影网格，以连续数组保存可能与射线相交的三角形。查询仍执行原来的有限三角形求交，保留 BVH 访问顺序和并列命中规则；过大的候选列表、非法投影或大世界坐标下的数值消差会回退原 BVH。

固定射线的三角边、叉积和行列式可逐姿态缓存。仅需要内外分类的面中心与端点先检查原有贴边例外，再执行相同的内部判定；外部点不再额外搜索完整最近面，内部点仍返回相同的最深包围组件及最近边界。返回的外部证据没有间距或背面信息，不用于证明接触余量。相关测试逐位比较命中结果和最终网格，并记录实际三角遍历量。

## 性能与验证

交互预览默认上限 60 FPS。窗口失焦时暂停动画及后台物理；最小化时等待窗口事件，不持续积累补算任务。沿用已有线程数量、正常系统调度与有界后台发布。

`hair_asset_test` 检查原始参数提取、绑定、资产保存、旧格式兼容、完整人物导出与失败原子性。`hair_body_collision_test` 检查真实几何接触、薄面连续检测、运动身体、单位、表情和 BVH 查询范围。`hair_surface_contact_test` 检查蒙皮后网格修正、固定区保留、单位和实例变换。`hair_solver_test` 检查确定性、惯性、静止、附着、当前帧一致性及运动手臂。`hair_preview_worker_test` 使用实际 VMD 与人物，检查头发、裙腰、身体、表情、局部网格修正和后台取消的一致性。

`hair_surface_quality_test` 是离线质量检查：逐 tick 模拟整段 9.2 秒动作，并扫描全部 10,702 个有效头发顶点及三顶点均可动的发片三角面中心，对比独立求值的动画人物表面。所有顶点的原始穿透值、源动画交叠、纯根部、自由远端、刚性区域都分别保留。可动区域和自由面中心执行 5 mm 原始穿透上限，不减去源动画交叠；只有绑定阶段明确识别的头皮内部附着点使用独立的 1.501 mm 头部局部漂移门槛。报告同时给出全部顶点原始值是否满足 5 mm，不能把“可动区域通过”称为所有埋入发根都已脱离头皮。

`hair_rest_stability_test` 将真实动画固定在 2.8 秒姿态，关闭测试副本的风，继续模拟 10 秒。它独立记录全部自由顶点的真实蒙皮和网格偏移轨迹，要求最后 2 秒的位移包围盒直径小于 2 mm、速度小于 0.02 m/s，并检查最终全体自由顶点、自由面中心、发根和附着漂移。该测试用于防止“动画已经暂停，头发仍反复弹起”的回归。

```powershell
ctest --test-dir build/windows-release -C Release --output-on-failure -j1 `
  -R '^(hair_asset_test|hair_body_collision_test|hair_surface_contact_test|hair_solver_test|hair_preview_worker_test)$'
.\output\Release\bin\hair_rest_stability_test.exe --output build/hair_rest30.json
.\output\Release\bin\hair_rest_stability_test.exe `
  --hair Asset/Generated/MahiroCloth/Hair/Hair.hair.json --frames 601 --output build/hair_rest60.json
.\output\Release\bin\hair_surface_quality_test.exe --frames 277 `
  --hair Asset/Generated/MahiroCloth/Hair/Hair_Realtime30.hair.json `
  --output build/hair_quality30.json
```

编辑器的网格残留只统计当步实际查询的接触点，骨骼采样残留另行显示。它们用于定位求解状态；整段质量结论以独立离线扫描为准。三角面中心采样也不能构成连续整面的数学无穿透证明，仍需结合实际近景预览。

检查器的大量 CPU 蒙皮和逐顶点查询不属于运行时帧耗时；性能报告需分别记录头发步耗时、编辑器显示 FPS、完成的物理 tick 频率和后台延迟。编辑器还区分逻辑时钟、休眠 tick 和实际求解次数，不能把休眠后的时钟频率称为动态物理吞吐。`--start-time` 与 `--hold-at` 可用于离线指定姿态重新开始和静止收敛检查；编辑器对应参数是 `--time` 与 `--cloth-hold-at`。`--hair-test` 的 GPU 测试会同步回读并比较图像，其 HUD FPS 也不作为交互性能结果。

本功能使用骨骼链近似，精细发束间自碰撞、发丝级模拟和头发模拟结果烘焙尚未实现。没有可动头发骨权重的源发片继续沿用原始绑定。开放或相互穿插的非流形源表面不能提供严格数学实体，需结合实际可见结果检查。可调表面余量默认 1.5 mm，应通过实际接触校验调整，不能用扩大身体碰撞体的方式隐藏穿模。

本次附着位移预算适用于真寻及当前 VMD：该动作不修改头发骨局部平移/缩放，模型没有头发表情位移。未来若导入会改变这些量的动画或头发 morph，应按当前长度重新计算预算，或在生成资产时导入最大形变包络。

性能排查可设置 `MODEL_HAIR_PROFILE=1`，结束时输出蒙皮求值、运动检测、平滑、面接触、最终顶点检查和发布的阶段耗时。`MODEL_HAIR_SURFACE_REUSE=0` 关闭精确查询复用，`MODEL_HAIR_SURFACE_STATIC_CONTACTS=0` 恢复静止时的人工衰减路径，`MODEL_HAIR_BONE_SURFACE_CONTACTS=1` 强制粗骨接触，供回归对照；正常运行无需设置环境变量。强制旧接触策略可能重现反弹，不建议作为运行配置。`MODEL_HAIR_SLEEP=0` 关闭休眠，`MODEL_HAIR_MEASUREMENT_REUSE=0` 关闭精确骨采样测量复用，`MODEL_HAIR_INSIDE_ONLY=0` 与 `MODEL_HAIR_FAST_RAYS=0` 分别恢复完整最近面查询和原射线算术，用于测量优化收益。

### 2026-10-16 稳定性修订实测

测试使用真寻原模型、当前分离 Body、`MahiroTaitui` 9.2 秒动画和发布的 20° 运行时配置。完整扫描不扣除原始动画交叠，只有经绑定证据验证的 414 个头皮附着点单独检查漂移。

| 30 Hz 整段 277 帧、2,849,776 次自由顶点检查 | 最大原始穿透 1.500 mm |
| 同一段 3,451,420 次自由面中心检查 | 最大原始穿透 1.677 mm，无样本超过 2 mm |

| 60 Hz 固定姿态 10 秒、最后 2 秒 | 同样收敛并休眠，位移及速度均为 0，最终自由顶点/面中心穿透均为 0 |

报告保存在工作目录 `build/hair_final_quality30.json`、`build/hair_default_quality60.json`、`build/hair_final_rest30.json` 和 `build/hair_final_rest60.json`。60 Hz 整段扫描在等价查询加速之前完成；加速另经合成和真实六姿态的命中/距离逐位对照及移动网格结果对照。

交互测试使用 Release、Intel RaptorLake-S Mobile Graphics、24 个逻辑处理器、可见窗口、60 FPS 上限、关闭裙摆物理。编译结束后独立运行，未截图或同步回读；180 帧预热后记录 600 帧：显示约 58.24 FPS，进程占整机 CPU 约 5.36%；头发实际动态求解约 11.36 Hz、每步约 83.9 ms，平均后台延迟约 2.67 秒。相比修订中的稳定基线 8.43 Hz / 112.2 ms 有改善，但**目前尚未达到 30 Hz 动态物理实时速度**，不能把窗口帧率称为物理帧率。详细报告为 `build/hair_final_playback_perf.json`。静止休眠的耗时也不代表播放时的性能。

当前主要瓶颈仍是后台线程的 CPU 表面碰撞查询。24 个逻辑处理器的整机占用率会摊薄单线程负载，因此低 GPU 占用和较低整机 CPU 百分比不能说明物理求解没有瓶颈。

## 接入 API 时的约束

模拟期间保持传入的 HairAsset 和目标 package 不变，并持续传入动画/IK 的原始求值姿态，避免把上次模拟结果再次作为动画输入。复制同一次调用的输出 pose 与 `SurfaceOffsets()`；该引用在后续 Step/Reset 后可能变化。显示时先普通蒙皮，再对该份新蒙皮结果调用一次 `ApplyHairSurfaceOffsets`，不能在已修正几何上重复叠加。

偏移使用锚骨局部坐标和源模型单位，调用者不应再次转成米。当前绑定要求每个头发 mesh 只有一个渲染实例，且实例变换与 skin.bindTransform 相同；其他实例布局应在生成前展开。运行时未修改源骨骼模型、动画、表情或原始材质。
