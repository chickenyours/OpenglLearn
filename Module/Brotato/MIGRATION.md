# Brotato 迁移记录与后续范围

迁移基线是用户提供的 `Unity2021_Botato` 目录，主场景为 `Assets/Brotato.unity`。源目录保持只读。战斗迁移完成至第六阶段武器几何校准；第七阶段（2026-10-05）开始在这套 ECS 基础上增加新玩法，先交付三敌人和升级成长，第八阶段继续完成远程、冲锋、精英、击退和范围爆炸，第九阶段第一批完成随机奖励池、被动物品与波间商店，第二批继续完成四级武器、六槽装备、合成与出售，第三批加入武器类别、四种词条、持续状态和四件物品，第十阶段第一批完成六波战役、Boss 和胜负结算，第二批完成五角色差异和三档难度，第十一阶段第一批完成怪物、刷新与强化核对及分波编队。源规则通过 `--source-rules` 保留，普通启动使用新设计。此前已修正 ECS 架构（2026-10-04）：独立系统查询组件，通用命令缓冲提交结构变更。本记录区分原脚本实际行为、场景／预制体覆盖值、迁移实现和新增设计，不以资源名称或商业版本功能推断该工程已经实现的玩法。

## 第十一阶段当前第一批：怪物、刷新与强化核对（2026-10-05）

核对结果：源工程只有一个实际怪物预制体／行为，不存在尚未迁移的另一个怪物类或怪物强化表。25 张怪物 Sprite 是美术，只有 40001 用于 NpcGo；当前九张接入了实际玩法，剩余十六张未设计 AI。本批增加的分波刷新、辅助怪与属性成长明确属于新设计，不能算作恢复商业版的完整怪物库。

`tools/audit_brotato_enemies.py` 扫描 .unity／.prefab 和脚本 GUID，生成 `build/brotato-enemy-source-audit.json`，含源行、绑定对象与 53 个输入哈希。查得 26 个游戏脚本、25 张 40001..40025 Sprite、唯一 EnemyNPC 绑定 `Assets/AI/NpcGo.prefab:338`，预制体移动速度 2.3；唯一 SpawnPosition 绑定 `Assets/Brotato.unity:86062`，364 个位置与 NpcGo GUID。EnemyNPC 只有出生／追踪／接触扣血／命中死亡／延迟经验；GamePlayUI 只增加波长，没有修改怪物生命、攻击、移动或组成。

另发现原刷新链每次都递归启动，包括 StartSpawningEnemys=false 时；RoleNext 又启动新的链，切波会累积协程。这属于生命周期缺陷，迁移基线的单计时器已避免它。本批正式补充随波次变化的密度、编队与突袭，具有明确上限。源规则的 0／1 秒整数等待、364 位置权重、1.5 秒出生／死亡延迟仍保留。

- 新增 ECS `SpawnDirector`，保存当前波、阶段进度、刷新和事件计时、独立随机数、成功／跳过编队数。第十五个系统 `EncounterSystem` 位于 Wave 与 Build 之间，查询组件后提交通用创建命令；没有窗口逻辑、模块回调或世界敌人数组。外部 archetype 的导演组件可直接被发现，独立 Context／Pipeline 可运行。原资源上的计时器只用于 source／显式关闭 encounters 的历史模式。
- 第一波普通与快怪，第二波重甲／射手，第三波冲锋／精英／强化变体，第四波起治疗者／召唤者。编队为 2／2／3／3／4／4，基础间隔 2／1.5／1.8／1.6／1.7／1.5 秒；前三成时间 ×1.15，末四分之一 ×.8，再叠加独立随机扰动和难度。第七秒起四秒突袭，每十三秒再次触发；虫群、相对两侧射手／重甲、多侧冲锋、辅助／重甲集群改变威胁组合。
- 编队位置沿场地边缘展开，距玩家至少四单位；极小自定义场地使用最远候选。保留出生预警，Boss 预留优先；普通编队整组检查场上实体和同一步请求，容量不足跳过、不积攒突发补刷。召唤也使用同一预留入口。
- 敌人出生保存 birthWave／damagePercent／growthSpeed／champion。六波生命为 100／140／200／280／380／500%，伤害每波 +8%、移速每波 +3.5%，再叠加难度。青色 SWIFT 增加速度和生命，金色 BULWARK 增加生命和伤害、降低速度；碰撞体和图片尺寸同步，血条显示身份，冲锋预警使用实际速度。既有怪物和在途攻击不回溯修改。
- 治疗者有 .75 秒绿色范围预警，恢复附近五单位内存活普通同伴最大生命的四分之一；不治疗自己、Boss、尸体或范围外目标。召唤者有一秒紫色预警，每次两只快怪，每个完整来源 generation 最多六名未死亡子怪。子怪没有 XP／材料奖励，距玩家三单位以内不召唤；击杀或击退可以取消辅助预警。

## 第十阶段第二批记录：角色属性与三档难度（2026-10-05）

本批属于明确的新设计。源角色按钮仅赋值图片，源难度只绑定 diff_0；没有将 UI 展示文字当作职业脚本移植。普通模式新增 profiles，默认 Well-Rounded／STANDARD 保持第一批基准，源模式仍使用外观角色和唯一难度。

- 玩家新增 CharacterProfile 和 RunRules ECS 组件，分别保存角色及本局难度。BuildSystem 按拥有者查询角色，与升级和物品相加后派生 CombatStats；外部 archetype 或没有该可选组件的玩家不会继承主玩家职业。新配置只在开局／重开初始化组件，生成工厂仍读取基础配置，不重复修改生命或伤害基准。

## 第十阶段第一批历史：六波战役、Boss 与结算（2026-10-05）

本批属于新增设计，原工程只提供恢复的 Boss 图片，没有对应完整技能、六波目标或结算规则。普通 ExpandedGameplay 启用 campaign；源规则和显式关闭 campaign 的历史测试继续使用各自规则。

- 默认六波时长 20／27／34／41／48／55 秒。第三波产生 70 HP 的 GUARDIAN，第六波产生 180 HP 的 FINAL GUARDIAN。目标需在本波倒计时结束前真实击杀，提前击杀继续生存至波末；超时未击杀即失败。中间波保留成长进入商店，免费恢复最大生命四分之一，向上取整、受缺失生命限制；末波胜利不生成商店或额外材料。
- Boss 是独立 archetype 上的 BossBrain，兼有基础 Enemy／Health／Transform；不扩展常规 EnemyKind 枚举，以保留旧六类统计。独立 BossAISystem 查询状态，普通 EnemyAI 跳过 Boss。移动查询可选 BossBrain，完整管线增至十四个系统。独立测试中的外部 Boss archetype 无需旧 EnemyBrain 或 GameModule 也能运行。
- 扇形五发、环形八发、锁定方向冲锋依次循环，已有 Line／Ring 批次显示对应预警。半血永久狂暴，扇形七发、环形十二发、冲锋速度提高且等待缩短；燃烧／减速沿用真实状态系统，Boss 只接受 10% 击退且预警不可打断。敌弹整组预留，容量不足取消整组并进入恢复。
- RunProgress 是玩家 ECS 组件，保存本波目标与最终 RunResult。目标创建成功后才标记出生，容量满时重试并优先于常规怪；目标判定查询 objective／wave 和真实死亡状态，不把删除或 ID 复用当成击杀。RunSystem 处理死亡优先、截止时刻与最终胜利，不回调应用模块。
- 玩家死亡为终局 DEFEAT，同步击杀 Boss 并死亡仍失败。结果捕获波次、击杀／Boss 数、等级、生命、材料、装备与物品数及战斗秒数；后续组件变化不改写结果。结算冻结模拟、清场所有战斗实体并清除玩法短音效，音乐继续。重开重新初始化本局，返回主页释放 Scene；普通战役不提供 V 复活或第七波。
- 导入 `40020.asset` 的原 RGBA 图片作为 GUARDIAN，六敌人 PNG、清单和目录头文件共八输出重复生成逐字节一致。旧 87 PNG、14 个唯一源输入哈希不变；源图片输出及源头文件输出保护均拒绝写入。当前 88 PNG，名称、角色和 AI 均由本项目新设计。

验证：21 个相关 CTest 全部通过，50.90 秒；新增九组 campaign 检查覆盖上述目标、容量、代际、独立系统、完整六波、冻结、同帧死亡、超时、值快照、清场与重开。音频桥增至九组。正常生命、实际奖励和赚取材料购物的 SMG 路线在无窗口及真实应用中均完成六波，225 秒、396 击杀、两个 Boss、25 级、六把武器、四件物品、材料 11、HP 200/200。26 个 OpenGL 场景全部通过，GL errors=0、batchDraws=1；包含普通整局、十个新短机制场景及十五个兼容检查。源霰弹／Mage／MAP 5 满波仍为 22 攻击／17 击杀／材料 2／HP 20／XP 32。胜负、狂暴、各预警、重开／主页和治疗 UI 已目视检查，入口与截图见 README。

本批复用已有 ECS 查询、代际句柄、命令回放和渲染批次，没有添加游戏专用引擎 API。完整自然路线仅证明该起始武器及选择可通关，不代表全部构筑平衡；短夹具注入伤害或压缩波次，只验证机制。奖励稀有度／权重、更多角色数值差异、可选难度、永久解锁／存档和通用压力下的性能优化继续留待后续。

## 第九阶段第三批历史：类别、词条与持续效果（2026-10-05）

本批规则为明确的新设计。原工程提供十件物品的 UI 美术，未提供对应完整属性／词条／组合结算。普通模式启用 traits，源模式和历史阶段夹具保留各自配置与随机行为。

- 元素（法杖／火把）、精准（Taser／匕首）、弹道（SMG／霰弹）按装备查询计数；每两把分别给所属类别的武器燃烧伤害 +1、暴击率 +10%、攻击频率 +10%。购买、合成、出售后立即重算，不叠加旧派生值；跨 archetype 接纳有效完整拥有者和格位。
- 武器保存 Burning／Chilling／Piercing／Vampiric 词条与独立暴击随机流。商品为普通 60%、各词条 10%；无穿透行为的类型转回普通。溢价 3，锁定完整商品，合成保留所选词条。攻击开始时生成完整 Damage 值，霰弹四弹共用一次暴击，未发射不消耗随机数；换波保留流，重开清空词条。

## ECS 架构修正（2026-10-04）

前五阶段真实使用了 ECS 存储和 Pipeline，但七个 System 都转发 `GameModule`，主要循环依靠模块私有实体列表，因此未充分达到用迁移驱动 ECS 架构的目标。本轮移除这些列表和转发，把更新实现交给 Wave / Movement / Weapon / Projectile / Contact / Pickup / Presentation 系统。`GameModule` 只保留生命周期、装配、固定步和公开接口；`GameWorld` 是配置、运行数据、实体关系、工厂 archetype、事件和命令缓冲的集合，没有玩法更新方法。

- 常规更新通过 `ChunkQuery` 的组件数组覆盖所有匹配 archetype；统计、容量、清场和显示提取也由查询决定，不要求实体先经过游戏工厂登记。
- 引擎新增 `ChunkView::Entity`、查询 `Count`、完整代际 `GetEntityHandle` 和 `TryGetComponent`。缺少动画或速度组件不妨碍一个有碰撞组件的敌人被击杀与延迟结算；无此组件时跳过相应附加操作。
- 通用 `CommandBuffer` 在查询结束后先销毁、后创建；玩法普通生成与效果创建分两个缓冲，维持此前先普通生成、后表现生成的顺序。波次完成丢弃未提交请求，再按组件查询清场。异常回滚、重复删除、旧 generation 和失效 archetype 的约定见引擎说明。
- 渲染提取复制显示值后排序，绘制端不借用组件指针；玩家／武器拥有者／目标仍是明确实体关系，可以通过代际检查后随机访问。
- 寻敌距离或弹丸命中时间完全相同时，以较小 EntityID 决胜，避免 swap-delete 的行重排决定目标。跨实体更新顺序为查询顺序，不承诺保留旧列表在所有极端同时命中情况下的顺序。武器时间、范围、伤害和源几何近似未更改。
- 当前 Pipeline 仍串行，读取／写入声明没有自动并行调度；现有句柄仍无全局 Scene 身份。Query 缓存须在 archetype 变化后刷新，组件指针不能跨结构变更。Enemy／Pickup 的容量在销毁后的创建回调中检查，超限请求会撤销刚创建的实体，可能推进其 ID generation，但不会保留超容量对象。

验证：14 个 CTest 目标、11 个真实 OpenGL 场景通过。新增玩法架构测试证明另一 archetype 中的实体无需登记即参与更新、显示和清场，独立 MovementSystem 无需 GameModule 即可运行；引擎测试覆盖查询与命令边界。该轮满波结果仍与第五阶段一致，具体命令与结果见 README。武器几何在后续第六阶段实现。

## 通用行为与第一阶段差异

1. **固定步与可复现随机序列。** 模拟为 120 Hz，默认随机种子 2026，重新开始重置种子。它保留规则而不复刻 Unity 的 Update / FixedUpdate / 协程逐帧时序或随机流。单次 Advance 限制输入时间至 0.25 秒、最多执行 8 个子步，超出的整步积压会丢弃，避免卡顿后无限追帧。
2. **整数 XP。** 2／100 替代 0.02／1，避免浮点累加和 UI 精确相等判断使升级门槛漂移。XP 仍在死亡延迟完成时结算，未改成命中立即加经验。
3. **波末未兑现 XP 仍丢失。** 波末清除尚处死亡延迟的敌人，不补发该经验；这是保留原规则，不计作修复。波末未拾取材料也随清场消失。
4. **单个刷怪计时器。** 源 StartSpawning 协程永久递归，RoleNext 再调用 StartSpawningS 会叠加多个循环。迁移每局只保留一个计时器，防止刷怪速率随切波意外倍增。
5. **临时实体有界。** 法杖与 SMG 弹丸寿命上限 4 秒；霰弹按原默认 0.15 秒清除。默认敌人最多 256、弹丸最多 256、材料最多 512。达到上限时拒绝额外创建，避免原始无界临时对象增长。上限包含相应列表中的出生／死亡阶段实体。
6. **独立 2D 碰撞实现。** 第一阶段使用相对运动圆形扫掠；第二阶段扩展为有方向胶囊扫掠，圆是半长为零的特例，弹丸保留最早命中并消费一颗弹丸。玩家接触和拾取仍使用圆形重叠；没有 Box2D 的推挤、刚体分离、敌人间阻挡或完整碰撞层矩阵。因此运动轨迹和贴身战斗细节不承诺逐帧等价。
7. **第一阶段视觉近似。** 使用静态 PNG、左右翻转、简化出生闪烁和死亡姿态，暂未导入 Animator、逐帧动画、粒子、伤害飘字、拾取音效及原 UI。角色选择结果先固定为 Well-Rounded 图标；收集物固定为 Addition 默认图片；地板固定一张瓦片。武器挂点、出生标尺寸与 HUD 为新渲染中的简化布局，不是整个 Unity 层级的自动转换。
8. **独立状态机。** Playing / Paused / WaveComplete / Dead 替代全局 Time.timeScale 和 UI 激活的隐式控制。波次面板停留期间玩法暂停；第三阶段新增会话层处理主页和菜单。

原相机跟随夹紧范围为 x `[10.1,12.04]`、y `[-7,7]`。此值属于原镜头布局数据；不能据此宣称已复刻其设备适配、原 UI 安全区域和 Canvas 缩放。

### 霰弹预制体和动画证据

`SpawnMove.prefab` 根对象没有 Rigidbody2D，挂载 `BulletGun.controller → MoveGun.anim` 和 `DestroyTime`；四个 BulletB 子对象各有 SpriteRenderer、横向 CapsuleCollider2D 和 gravityScale=1 的动态刚体。它使用普通长枪弹贴图；不是火焰发射器。`w6.cs` 虽声明 `bulletSpeed=105`，发射代码只实例化预制体，没有给子弹速度赋值。

### 命中特效与时间规则

出生标仍按 `EnemyNPC.LoadingEnem` 的时间显示：`[0,.2)` 可见，`[.2,.5)` 隐藏，`[.5,1.5)` 可见，到 1.5 秒启用身体与碰撞。敌人死亡身体动画 .5 秒结束后不可见，但实体继续等待至 1.5 秒才发 XP；可见尸体的缩放结束不能提前结算经验。

`NpcGo.PrefabParticle` GUID `68797e6c0aa224340870701e3a501331` 指向 `DirectionalHitParticles.prefab`。UVModule 使用 `particle_9.asset`，并非按粒子材质的空 MainTex 推测图片。一次发射 6 个，寿命 .5 秒，速度随机 1..8，尺寸随机 .1...28，颜色 `(.8018868,.19290671,.1970778,1)`；归一化大小曲线由 `(0,1,0,0)` 与 `(1,0,−2,−2)` 两个 Hermite 点定义，即 `1−t²`。本轮保留这些值，以固定 +X、±7° 的二维窄锥模拟原 3D 发射方向；不声称完整实现 Unity ParticleSystem 的三维形状与深度采样。

飘字 Value 的父 Canvas 直接位于 NpcGo 根下，不继承 Monster_All 的死亡缩放。Canvas 的 local Z 为 `.972`，经 NpcGo 根 X 轴 −90° 旋转后成为世界 Y 偏移；结合 RectTransform 的 anchored X `−.003`，最终文本位置为敌人坐标 + `(−.003,.972)` + AddIt 采样位置。因此出生文字位于敌人原点上方约 .214 单位，而非脚下 .758 单位。生成目录保存这项父级位移。

源粒子预制体没有删除脚本，非循环播放结束会留下空对象。本轮 Effect 实体在显示寿命到达时回收。装饰飘字在每次有效击杀触发，显示白色随机 `+1..8`、字号 .25；它不是实际伤害、XP 或材料。源 AddIt 没有淡出，位置结束后保持，直到关联死亡延迟完成。本轮效果采用独立确定性散列，不消耗玩法刷怪／掉落随机流。

ECS 新增 `ActorAnimation`、`Effect` 与末尾 `PresentationSystem`。默认最多 512 个 Effect；外部音频消费的值事件队列最多 256 条，容量满时记录丢弃计数，避免消费者不轮询造成无限增长。事件捕获发生时位置和代际句柄，不让音频保存组件地址。重开、波次清场、回主页和 Shutdown 均处理特效与事件生命周期。

音频模块增加按 voice 暂停／恢复并保留播放游标。Brotato 桥最多保留 32 个玩法短声音；暂停冻结这些声音，UI 与音乐继续。死亡、重开、切波和回主页清除短声音。源 `Time.timeScale=0` 本身并不会暂停 AudioSource，因此短音效冻结与生命周期清理是迁移改进；复活不重播已清除的旧击杀音。`M` 与 `--mute` 是新增静音入口。

### 通用渲染能力与可重现导入

`Render::Animation` 是不依赖 Brotato 的纯曲线／Pose 采样接口，支持节点化位置、缩放、连续角度和透明度。生成目录记录源 bind pose，采样只覆盖绑定通道。精灵批次新增 `SpriteAffine`，使用二维仿射基向量保留父级非均匀缩放、子节点旋转产生的斜切，避免将角色分层近似成角度相加与尺寸相乘。源几何矩阵只用于显示，不改变原碰撞圆。

新资源是两腿、固定身体／阴影、高亮与命中粒子共 5 PNG，总图片数 65；导入同时生成六条 Clip、9／3 个角色／敌人层级节点、5 个角色 pivot，以及 [presentation_manifest.json](../../Asset/Brotato/presentation_manifest.json)。重复导入的 5 PNG、manifest、header 共 7 文件逐字节一致，原 60 PNG 的 SHA-256 均未变；音频的 8 WAV 与 manifest 也重复导入逐字节一致（同一 ffmpeg 版本）。源码保持只读，展示／音频导入器都拒绝输出到源目录内；完整原 UI、起始武器选择、玩家 Smoke 发射器和其余真正有逻辑的内容不计入第四阶段完成范围。

第四阶段验证完成（2026-10-03）：10 个相关 CTest 目标全部通过，耗时 8.56 秒，包括 18 组基础玩法、16 组武器、16 组会话、18 组表现、6 组音频桥，以及菜单布局、三个渲染目标和通用音频模块。飘字 Canvas 位移的最后修正后，重新编译并单独复验 18 组表现测试，通过耗时 .81 秒；通过实际 `run_brotato.bat` 再跑 death 场景，输出 `GL errors=0`、7 个效果实体和 13 个玩法精灵，截图／离线 WAV 已更新。

六个固定表现 GPU 场景、三轮菜单往返、2400 ticks 完整波次及静音场景共 9 个入口通过。9 份离线 WAV 均为 48 kHz／双声道／PCM16，静音文件全零，其余有非零混音数据。WinMM 的 48 kHz 与 44.1 kHz 静音设备流启停也通过；这证明设备路径可打开关闭，不作为人工听音结论。完整入口及截图链接见 README。前三阶段测试结果继续作为历史，不代替本轮验证。

## 第六阶段历史：源武器几何校准

`tools/import_brotato_weapon_geometry.py` 沿脚本绑定读取六个实际根、SpriteRenderer 引用、TransformShoot、ShootPrefabe、弹丸 prefab、六段激光和四条 `MoveGun.anim` 路径。输出 [weapon_geometry_manifest.json](../../Asset/Brotato/weapon_geometry_manifest.json) 和 `weapon_geometry_catalog.h`，保存 fileID、源行、局部变换、Sprite PPU／pivot、动画端点和 40 个源输入哈希。导入不改动图片；重复生成两文件逐字节一致，已有 72 PNG 和引用源文件哈希均未变，两个源目录输出保护检查正确拒绝。

源 `Update` 使用 `Quaternion.AngleAxis(angle, Vector3.forward)` 覆盖旋转根的**世界**朝向，因此动态坐标只组合该根以下的子变换，不重复叠加初始父级／根四元数。初始法杖根约 30.4°，其他五个根的 XY 投影有反射：X 轴向上、Y 轴向右。`Weapon::reflected` 保存此状态，瞄准清除反射，近战返回恢复初始姿态。导入器拒绝非单位根缩放、无法用角度／反射表达的初始根或边缘朝向的精灵，避免静默扁平化错误。

| 几何对象 | 当前实现 |
| --- | --- |
| 武器物理根与检测源 | `Transform` 保留源根位置，寻敌使用独立 `scriptOffset`；法杖偏移 `(.014,-.029)`，其余根在玩家原点 |
| 武器显示矩形 | `RenderExtract` 使用子偏移、二维基向量、真实 Sprite 尺寸与非中心 pivot；Simple Sprite 不采用 renderer 的序列化 `m_Size` |
| 弹丸出生点与方向 | 使用真实 TransformShoot；法杖／SMG 速度仍沿根到目标，枪口偏移不改变瞄准方向；事件也捕获真实发射位置 |
| 双管霰弹 | 四条动画路径从霰弹射击点出发，位置和弹丸朝向随根旋转；源零切线 Hermite、0.25 秒动画与 0.15 秒寿命保留 |

## 展示资源与空实现的边界

`Assets/Scripts` 只有 26 个自定义脚本；大量文件属于纹理、预制体、动画、FairyGUI、Spine 示例和其他插件。文件数量不能作为完整游戏系统已经实现的证据。

- `DataController.cs`、`BooleanManager.cs` 只有空 Start / Update；`LaserManager.cs` 是空类。
- `CharacterSetter.cs` 只将按钮 Icon 的 Sprite 赋给角色，没有应用角色 UI 中写出的生命、速度、收获等修正。后续角色数值需要明确的数据与规则依据，不能当成已有属性系统移植。
- `UIManager.cs` 读取 `PlayerPrefs.GetInt("Cash")` 展示余额；已审查脚本未发现完整购买扣款、刷新、锁定商品、背包、合成或物品属性结算。商店图片和面板存在不等于经济系统已完成。
- `ItemSetter.cs` 随机选择掉落物图片，不提供物品属性或奖励表；`DestroyTime.cs` 只提供延迟删除。其他敌人、Boss、建筑和大量武器美术不能自动算成已实现的 AI、技能或战斗系统。
- 源 UI 存在按钮绑定和对象显隐流程；第三阶段已核对开始、返回、暂停、死亡与波次按钮，其余页面仍须逐项审查，不能仅靠脚本文件名推断行为。`CompoenentManager.cs` 是 4 秒后显示主页的加载流程，非资源管理系统。
